## نگاه کلی

یدک‌یار یک فروشگاه اینترنتی قطعات یدکی است که کاربر به‌جای گشتن در فهرست، **داخل محفظهٔ موتور خودرو را
به‌صورت سه‌بعدی می‌بیند** و روی خود قطعه کلیک می‌کند. برای هر قطعه چهار گزینهٔ خرید در سطوح
اصلی کارخانه، OES، باکیفیت و اقتصادی نمایش داده می‌شود.

| | |
|---|---|
| خودروهای پشتیبانی‌شده | جک S5 · هیوندای النترا (AD) · تویوتا کرولا (E170) |
| محصولات | ۳۸۸ کالا · ۳۳ قطعه · ۴۰ برند · ۱۴ دسته‌بندی |
| تصاویر | ۱۳۲ کارت برند + ۳۲ عکس اختصاصی قطعه |
| وابستگی خارجی | **هیچ** — بدون npm، بدون CDN، بدون فریم‌ورک |
| حجم | ۱۱ مگابایت |

## اجرای محلی

```bash
git clone https://github.com/<USER>/yadakyar.git
cd yadakyar
python3 -u server.py          # http://localhost:8080
```
پنل مدیریت: `/admin-login.html` — نام کاربری `admin` · رمز `admin123` (قبل از انتشار حتماً عوض کنید).

## صداقت داده‌ها

شماره‌های OEM از منابع عمومی سازندگان استخراج و در فیلد `source` هر محصول ثبت شده‌اند.
قیمت‌ها **تقریبی** و بر پایهٔ بازار ۱۴۰۴ هستند. داده‌ها فعلاً در `localStorage` نگهداری می‌شوند؛
برای فروش واقعی باید فقط لایهٔ `db.js` به یک API متصل شود — جزئیات در `DEPLOY.md`.

## مستندات فنی

# یدک‌یار — پلتفرم شناسایی و فروش قطعات خودرو

## اجرا
از **پیش‌نمایش زندهٔ پورت 8080** استفاده کنید (پیش‌نمایش تک‌فایلِ ورک‌اسپیس، فایل‌های assets را بارگذاری نمی‌کند).
یا محلی: `cd site && python3 -m http.server 8080`

## ورود مدیر
`admin-login.html` → نام کاربری `admin` / رمز `admin123` (از پنل ← تنظیمات قابل تغییر)

## معماری
```
site/
├── assets/css/app.css      Design System واحد (توکن رنگ، دکمه، کارت، جدول، فرم، مودال)
├── assets/js/seed.js       دادهٔ اولیهٔ کاتالوگ (تولیدشده — 212 محصول، 3 خودرو، 33 قطعه، 14 دسته)
├── assets/js/db.js         Repository Layer — تنها نقطهٔ اتصال به داده
├── assets/js/ui.js         UI Kit مشترک: هدر/فوتر/جستجوی زنده/کارت محصول/سبد/toast/modal

├── index.html              صفحهٔ اصلی + نمایش سه‌بعدی

├── shop.html               فروشگاه با Vehicle-Finder و فیلترهای کامل
├── product.html            صفحهٔ محصول (گالری، تب‌ها، سازگاری، OEM)
├── cart.html / checkout.html / order.html   سبد، تسویهٔ ۴ مرحله‌ای، پیگیری سفارش
```

## مدل داده (یکپارچه)
`Vehicle → hotspots[{partId,x,y}] → Part → Product(fitment: vehicleId, years, engines)`
هر محصول: `id, sku, oem[], oemVerified, source, brand, categoryId, partId, vehicleId, price, oldPrice, stock, images[], specs{}, warranty, active`

## تبدیل به محصول واقعی (Backend)
تنها فایلی که باید تغییر کند `assets/js/db.js` است: توابع `read/write` را با `fetch('/api/...')` جایگزین کنید.
هیچ صفحه‌ای مستقیماً به localStorage دست نمی‌زند.

## صداقت داده
- شماره‌های OEM فقط جایی درج شده که از کاتالوگ سازنده استخراج شده و با نشان «تأییدشده» و فیلد `source` مشخص است
  (Toyota 90915-YZZJ1 / 17801-0T030 / 87139-YZZ08 · Hyundai 26300-35505 / 28113-F2000 / 97133-F2000 · JAC 1109010U8010 / 1026106GAA / 1600010U1050 …)
- بقیهٔ OEMها خالی و با برچسب «ثبت نشده — توسط مدیر تکمیل شود» رها شده‌اند (ساختگی تولید نشده).
- قیمت‌ها **تخمین بازار ایران** هستند و در همه‌جا با این برچسب نمایش داده می‌شوند؛ از پنل مدیر قابل ویرایش‌اند.
- تصاویر، رندرهای تولیدشده‌اند (بدون مسئلهٔ کپی‌رایت) و مدیر می‌تواند عکس واقعی هر محصول را جایگزین کند.

## ۱) مدل چهار برندی (نسخهٔ ۷)

هر قطعه برای هر خودرو در **۴ سطح کیفی** عرضه می‌شود:

| سطح | کد | ضریب قیمت | گارانتی | نمونه برند |
|---|---|---|---|---|
| اصلی کارخانه | `genuine` | ۱٫۰۰ | ۱۸ ماه | Hyundai Mobis، Toyota Genuine، JAC Genuine |
| تأمین‌کنندهٔ اصلی (OES) | `oes` | ۰٫۷۶ | ۱۲ ماه | MANN-FILTER، NGK، Bosch، Denso، Textar، KYB |
| باکیفیت (Aftermarket) | `quality` | ۰٫۵۸ | ۹ ماه | Hi-Q، Behr Hella، Sachs، Valeo، Depo |
| اقتصادی | `economy` | ۰٫۴۲ | ۶ ماه | سرکان، پارس‌لنت، بهران، سپاهان‌باتری |

۳۸۸ محصول · ۴۰ برند یکتا · ۱۳۲ تصویر اختصاصی در `assets/img/brand/<partId>-<tier>.jpg`
(ساخت مجدد: `python3 ../mkbrandimg.py` سپس `python3 ../mkseed.py`).
تصاویر، عکس واقعی همان قطعه + رنگ‌بندی سطح کیفی + نام لاتین برند هستند؛ از عکاسی برندها کپی نشده‌اند.

## ۲) دستیار هوشمند (`assets/js/assistant.js`)

موتور **بازیابی و تطبیق محلی** روی کاتالوگ است، نه مدل زبانی؛ هیچ درخواست شبکه‌ای و هیچ کلید API ندارد.
نرمال‌سازی فارسی (ی/ک/ارقام/نیم‌فاصله) + امتیازدهی کلیدواژه + پاسخ‌های قاعده‌محور:
پیگیری سفارش، ارسال، گارانتی بر پایهٔ سطح، پرداخت، تفاوت اصلی/OES، خودروهای پشتیبانی‌شده،
ارزان‌ترین/بهترین، موجودی و جست‌وجوی عمومی با بازهٔ قیمت و شمارهٔ OEM.

## ۳) موتور به‌روزرسانی ساعتی قیمت (`price_worker.py`)

```bash
cd site
python3 price_worker.py --once   # یک اجرا
python3 price_worker.py          # حلقهٔ دائمی طبق interval_minutes
```
* تنظیمات از پنل مدیریت ← **تنظیمات ← به‌روزرسانی خودکار قیمت** وارد و در `price_config.json` ذخیره می‌شود.
* خروجی: `assets/data/prices.json` و گزارش ۵۰ اجرای آخر در `assets/data/price-log.json`.
* سایت در بارگذاری (حداکثر هر ۳۰ دقیقه) و پنل مدیریت با دکمهٔ «همگام‌سازی همین حالا» این فایل را می‌خواند.
* **محدودیت صادقانه:** مرورگر به‌خاطر CORS نمی‌تواند سایت دیگری را بخواند؛ این ورکر باید روی سرور اجرا شود.
  رعایت `robots.txt` و شرایط استفادهٔ سایت مرجع بر عهدهٔ بهره‌بردار است.
